# Лабораторная работа №4. Понимание фишинга
## Цель работы
 
Понять принцип работы фишинговых атак, научиться распознавать признаки поддельных веб-страниц и изучить способы защиты от подобных атак на практике, через контролируемую локальную демонстрацию на Flask.

## Используемые технологии
 
- Python
- Flask
- HTML
- JavaScript
- Tailwind CSS
- Локальное хранение данных (файл)
## Структура проекта
 
```text
phishing/
│
├── server.py
│
├── templates/
│   └── index.html
│
└── static/
    └── login_data.txt
```

---

| Файл | Назначение |
|---|---|
| `server.py` | Запускает локальный Flask-сервер и обрабатывает отправку формы |
| `templates/index.html` | Страница, имитирующая интерфейс оплаты |
| `static/login_data.txt` | Демонстрационное хранилище обработанных тестовых данных |

```text
Пользователь
     ↓
Страница оплаты
     ↓
Заполнение тестовой формы
     ↓
POST /submit
     ↓
Flask-сервер
     ↓
static/login_data.txt
     ↓
Сообщение об ошибке сервера
```
Главная страница доступна по адресу `http://127.0.0.1:5000/`. После заполнения формы браузер отправляет POST-запрос на `/submit`, Flask обрабатывает данные и сохраняет **номер карты**, например

```text
Card: 111 111 111 111 | Expiry: 13/22 | CVV: 1111
```

На странице размещено предупреждение:
 
> ⚠️ Тестовый режим. Не вводите настоящие данные банковской карты.
 
## Запуск проекта
 
```bash
python server.py
```
 
После запуска Flask отобразит локальный адрес:
 
```text
http://127.0.0.1:5000/
```
 
Откройте его в браузере — появится демонстрационная страница оплаты.
 
## Тестирование
 
1. Заполните форму тестовыми данными.
2. Нажмите **«Проверить оплату»**.
3. Форма отправит данные на Flask-сервер.
4. Сервер сохранит безопасную демонстрационную запись в `static/login_data.txt`.
5. Пользователь увидит сообщение:
   > ⚠️ Сервер не отвечает
   и информацию о том, что платёж не был завершён.
Так была проверена связь между HTML-интерфейсом и Flask-сервером.
